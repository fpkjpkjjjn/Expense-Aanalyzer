# Expense Analyzer — JSON API (backend для мобильного приложения)

## Запуск

```bash
pip install -r requirements.txt
python api.py
```

Сервер поднимется на `http://0.0.0.0:5000` — доступен и с компьютера
(`127.0.0.1:5000`), и с телефона в той же Wi-Fi сети по IP компьютера.

**Как узнать IP компьютера в локальной сети:**
- Windows: `ipconfig` → строка "IPv4-адрес"
- macOS/Linux: `ifconfig` или `ip addr` → обычно `192.168.х.х`

## Эндпоинты

### `GET /api/health`
Проверка, что сервер жив.
```json
{"status": "ok"}
```

### `POST /api/analyze-transactions`
Основной эндпоинт — принимает список трат, введённых вручную в приложении
(JSON, не файл).

Тело запроса:
```json
{
  "transactions": [
    {"date": "2026-09-01", "description": "Pyaterochka", "amount": 1250.50},
    {"date": "2026-09-05", "description": "Uber", "amount": 340.00}
  ]
}
```

Пример через curl:
```bash
curl -X POST -H "Content-Type: application/json" -d '{
  "transactions": [
    {"date": "2026-09-01", "description": "Pyaterochka", "amount": 1250.50}
  ]
}' http://127.0.0.1:5000/api/analyze-transactions
```

Ответ (одинаковый формат для обоих эндпоинтов анализа):
```json
{
  "total": 1590.5,
  "by_category": [
    {"category": "Groceries", "amount": 1250.5},
    {"category": "Transport", "amount": 340.0}
  ],
  "by_week": [
    {"week": 36, "amount": 1590.5}
  ],
  "top_transactions": [
    {"date": "2026-09-01", "description": "Pyaterochka", "amount": 1250.5, "category": "Groceries"}
  ]
}
```

### `POST /api/analyze` (оставлен для совместимости)
Старый способ — загрузка CSV/Excel файла (`multipart/form-data`, поле
`statement`). Приложение теперь им не пользуется, но эндпоинт работает,
если понадобится в будущем.

Ошибки возвращаются в JSON с соответствующим HTTP-кодом:
- `400` — некорректные данные (пустой список, не хватает полей)
- `422` — не удалось проанализировать (например, неверный формат даты)

## Структура

```
api.py          — Flask-эндпоинты
analyzer.py     — анализ трат (категоризация, суммы по категориям/неделям)
categorizer.py  — определение категории по описанию траты
```

Категоризация трат (`categorizer.py`) работает по ключевым словам и нечёткому
сравнению — не нужно указывать категорию вручную в приложении, она
определится автоматически по описанию (например «Пятёрочка» → Groceries).

## ИИ-категоризация (локальная ML-модель)

Категория трат теперь определяется не только по ключевым словам, но и
локальной ML-моделью (`ml_categorizer.py`) — без внешних API, полностью офлайн.

**Как это работает:**
1. Модель стартует с базовых примеров, сгенерированных из ключевых слов в `categorizer.py`
2. Если модель уверена в своём предсказании — использует его (`category_source: "ml"`)
3. Если не уверена — откатывается на старую категоризацию по ключевым словам (`category_source: "rules"`)
4. Каждое исправление категории от пользователя дообучает модель — со временем
   качество должно расти по мере использования приложения

Файлы `ml_model.joblib` и `training_data.json` создаются автоматически при
первом запуске — это обученная модель и накопленные примеры соответственно.
Если хочешь сбросить обучение и начать заново — просто удали оба файла.

### `POST /api/feedback`
Отправляет исправление категории — модель дообучается на этом примере.

```bash
curl -X POST -H "Content-Type: application/json" -d '{
  "description": "U Bacusa Kosice",
  "category": "Dining"
}' http://127.0.0.1:5000/api/feedback
```

### `GET /api/categories`
Список всех доступных категорий (для выбора в приложении при исправлении).

**Важное ограничение:** это простая модель (TF-IDF + Naive Bayes), а не
большая языковая модель — она хороша ровно настолько, насколько разнообразны
примеры, на которых она обучена. На первых порах будет часто откатываться на
старую категоризацию по ключевым словам, и это нормально — станет точнее по
мере использования и исправлений.

## АИ-ассистент: ввод трат свободным текстом

`ai_assistant.py` — понимает обычный человеческий текст и сам достаёт из него
дату, сумму, валюту, описание и категорию.

### `POST /api/parse-expense`

```bash
curl -X POST -H "Content-Type: application/json" -d '{
  "text": "потратил 20 евро на кофе вчера"
}' http://127.0.0.1:5000/api/parse-expense
```

Ответ:
```json
{
  "date": "2026-09-16",
  "description": "кофе",
  "amount": 20.0,
  "currency": "EUR",
  "category": "Dining",
  "category_source": "rules",
  "category_confidence": 0.43
}
```

Понимает русский, словацкий и английский вперемешку:
- "потратил 20 евро на кофе вчера"
- "minul som 15€ na taxi"
- "spent $8.50 on lunch today"
- "Kaufland 45.30 2026-09-01" (можно и как обычная запись)

**Как это устроено на самом деле** (без розовых очков):
- Сумма и валюта достаются регулярными выражениями — для чисел это надёжнее,
  чем ML, и не черный ящик
- Дата — по словам "сегодня/вчера/dnes/včera/today/yesterday" или явной дате
  ГГГГ-ММ-ДД, иначе по умолчанию сегодня
- Описание — то, что осталось после вычитания суммы/даты/служебных слов
  ("потратил", "minul", "spent" и т.п.)
- **Категория — единственная часть, которая является настоящей обучаемой
  ML-моделью** (`ml_categorizer.py`), она же дообучается на исправлениях
  пользователя через `/api/feedback`

Если в тексте не нашлась сумма — вернётся ошибка `422` с тем, что удалось
разобрать (`"partial"`), чтобы приложение могло попросить уточнить сумму,
не теряя остальное.

## Импорт своей базы категоризации + поддержка кириллицы

Если у тебя уже есть готовая база "магазин → категория" (например, выгруженная
из другого приложения) — её можно массово загрузить в модель одной командой,
вместо того чтобы дожидаться, пока модель научится сама на исправлениях.

### Формат файла
CSV без заголовка, три колонки через запятую:
```
описание,сумма,категория
```
Сумма не используется (нужна только для сохранения формата), но должна
присутствовать. Категории — любые строки, не обязательно из встроенного
списка. Пример:
```
Lidl,65.00,Groceries
Slovnaft,45.00,Benzin
Slovenska sporitelna,3.50,Banky a financie
```

### Запуск
```bash
python import_training_data.py moja_baza.csv
```

**При первом импорте** синтетические стартовые примеры (сгенерированные из
`categorizer.py`) полностью заменяются твоей базой — иначе сотни generic
примеров забили бы числом твои настоящие данные. При повторном импорте новые
примеры добавляются к уже накопленным.

### Поддержка кириллицы

`text_normalize.py` транслитерирует кириллицу в латиницу и снимает словацкую
диакритику **одинаково** и при обучении, и при вводе. Поэтому после импорта
базы с названием "Lidl" — модель понимает и "Lidl", и "ЛИДЛ", и "lidl" как
один и тот же магазин, без необходимости дублировать записи на разных языках.

```
Lidl      -> lidl
ЛИДЛ      -> lidl
ČSOB      -> csob
ВУБ банка -> vub banka
```

Модель дополнительно использует посимвольные n-граммы (а не целые слова),
поэтому терпима к небольшим расхождениям в написании — не обязательно
транслитерация 1:1, "chsob" и "csob" всё ещё распознаются как похожие.

**Важно:** если модель не уверена в своём предсказании, старый откат на
встроенные английские ключевые слова (`categorizer.py`) срабатывает только
если предложенная им категория реально существует среди твоих собственных
категорий — иначе используется собственное (пусть и не самое уверенное)
предположение модели, а не чужая категория из встроенного списка.

## Обновление: подключена твоя собственная модель (skynet)

Встроенная категоризация (`ml_categorizer.py`, `categorizer.py`) заменена на
твою собственную обученную модель — `train.py` + `predict.py` + твоя база
(`sample_data_sk`). Файлы `skynet_categorizer.py` и `text_normalize.py`
подключают её к API без переделки `analyzer.py`/`api.py`.

### Что нужно сделать
1. После того, как `train.py` в твоей папке `skynet` отработает и создаст
   `model.joblib` — скопируй этот файл сюда, в корень `expense-analyzer-api`
   (рядом с `api.py`)
2. `pip install -r requirements.txt`
3. `python api.py`

### Категории теперь твои
`GET /api/categories` возвращает список категорий из твоей модели
(`pipeline.classes_`), а не мой старый захардкоженный список.

### Кириллица
`text_normalize.py` встроен прямо в `TfidfVectorizer` через `preprocessor=`
(см. `train.py`) — поэтому "ЛИДЛ" и "Lidl" распознаются как один и тот же
магазин без дублирования данных.

### Исправления категорий (/api/feedback)
**Важное отличие от старой встроенной модели**: эта модель не дообучается
мгновенно на лету (в отличие от прежней Naive Bayes). Исправления от
пользователя копятся в `corrections.csv` рядом с `api.py`. Чтобы включить их
в модель:
```bash
python merge_corrections.py sample_data_sk corrections.csv
python train.py sample_data_sk model.joblib
```
Первая команда переносит накопленные исправления в твою основную базу и
очищает `corrections.csv`, вторая — переобучает модель на обновлённых данных.
Скопируй новый `model.joblib` в бэкенд и перезапусти `api.py`.
