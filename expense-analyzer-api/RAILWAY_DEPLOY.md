# Деплой бэкенда на Railway

## Зачем
Твой сайт на Netlify работает по HTTPS. Backend на своём компьютере — по
обычному HTTP и виден только в домашней сети. Браузер блокирует запросы с
HTTPS-страницы на HTTP-адрес (mixed content), поэтому категоризация не
работала вне локальной сети. Railway даёт бэкенду постоянный HTTPS-адрес,
доступный из любой сети.

## Шаг 1. Подготовка
В этой папке уже всё готово для Railway:
- `Procfile` — говорит Railway, как запускать сервер (через `gunicorn`,
  production-сервер, а не встроенный dev-сервер Flask)
- `requirements.txt` — добавлен `gunicorn`
- `api.py` — теперь слушает порт из переменной окружения `PORT` (Railway
  назначает его сам), а не захардкоженный 5000

**Важно:** положи в эту же папку свой обученный `model.joblib` — без него
категоризация не заработает и на Railway.

## Шаг 2. Залей код в GitHub
Railway разворачивает проект из GitHub-репозитория. Если у тебя ещё нет
репозитория для бэкенда:
1. Создай новый репозиторий на github.com (например `expense-analyzer-api`)
2. Залей туда содержимое этой папки, включая `model.joblib`
   (обрати внимание: `.gitignore`, если есть, не должен исключать `*.joblib`)

## Шаг 3. Создай проект на Railway
1. Зайди на railway.app, войди через GitHub
2. **New Project** → **Deploy from GitHub repo** → выбери свой репозиторий
3. Railway сам определит, что это Python-проект (по `requirements.txt` и
   `Procfile`) и начнёт билд — дай ему пару минут

## Шаг 4. Проверь, что заработало
1. В настройках проекта на Railway найди вкладку **Settings** → **Networking**
   → **Generate Domain** — получишь адрес вида `https://твой-проект.up.railway.app`
2. Проверь в браузере: `https://твой-проект.up.railway.app/api/health` —
   должно вернуть `{"status": "ok"}`
3. Проверь категории: `https://твой-проект.up.railway.app/api/categories` —
   должен вернуть список твоих словацких категорий

## Шаг 5. Подключи приложение к новому адресу
В проекте приложения (`expense-analyzer-mobile`) открой `src/config.js` и
замени адрес на новый:

```js
export const API_BASE_URL = "https://твой-проект.up.railway.app";
```

Пересобери и передеплой сайт на Netlify с этим изменением — теперь и сайт,
и бэкенд будут по HTTPS, mixed content больше не будет блокировать запросы,
а backend будет доступен из любой сети, не только домашней.

## Если что-то пошло не так
- **Ошибка при билде на Railway** — открой вкладку **Deployments** → лог
  билда, там будет видно, на каком шаге упало (чаще всего — несовместимая
  версия пакета или файл `model.joblib` не попал в репозиторий)
- **`/api/categories` возвращает ошибку про model.joblib** — модель не
  загрузилась, скорее всего файл не попал в git (проверь `.gitignore`)
- **Долгий первый запрос после простоя** — на бесплатном тарифе Railway
  проект может "засыпать" при отсутствии трафика и просыпаться по первому
  запросу с задержкой в несколько секунд — это нормально
